## Security assessment

The reviewed endpoints use `AuthGuard`, role and module-feature guards, and tenant-scoped queries. Non-super-admin tenant overrides are rejected in Correlation, Playbooks, and Monitoring. SOAR requires initiator confirmation and an independent approval before sandbox execution; the connector is restricted to `.test` targets and fixed loopback, validates HMAC signatures, request fields, and freshness, and its mock rejects nonce replay (`backend/src/playbooks/sandbox-connector.service.ts:39-57`; `sandbox-client.ts:7-17`; `backend/qa-phase3b-mock-tool.cjs:23-28`). Correlation machine credentials bind to a tenant and support expiry/revocation (`backend/src/correlation/correlation-credentials.service.ts:76-87`). Monitoring uses tenant-keyed identity HMAC and strips the digest from finding detail, with retention/redaction logic (`backend/src/intelligence/monitoring-identity.ts:10-20`; `monitoring.service.ts:41-52,182-187`). Synthetic SOAR and Monitoring activation additionally require isolated QA flags and QA database names; no production mitigation or live monitoring endpoint is enabled by this PR. These properties are code-review observations supported by earlier focused tests, not a fresh penetration test.
