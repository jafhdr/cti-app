## Documented limits

- Evidence is **metadata only**. The application has no uploaded bytes to verify and makes no cryptographic file-integrity assertion. Legacy evidence is not retroactively represented as an immutable historical row until first revision; the synthetic `LEGACY_UNVERSIONED` view says so explicitly.
- Restrictive foreign keys and immutable history triggers protect normal application and SQL UPDATE/DELETE paths, but tenant-level deletion/export, backups, legal hold, and retention duration remain governance decisions. This phase does not claim comprehensive immutable retention.
- The investigation snapshot hash is a change detector for Case metadata, evidence metadata/revision IDs, and tasks. It is not a file digest. Activity count prevents later investigation events from silently reusing an approval. A new review is required after such a change.
- Existing V1 Cases with no P1-C history retain their legacy lifecycle while the feature is off. A tenant that enables P1-C must use the controlled closure path; V2 closed Cases remain protected by their history. P1-D reporting is not implemented.
